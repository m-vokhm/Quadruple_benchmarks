# CLAUDE.md

## О проекте

Бенчмарки для библиотеки **Quadruple** (https://github.com/m-vokhm/Quadruple, локально — `/home/misa/git/Quadruple`):
класс `com.mvohm.quadruple.Quadruple` — плавающая точка с 128-битной мантиссой и 32-битной экспонентой
(знак, `exponent` со смещением `0x7FFF_FFFF`, `mantHi`, `mantLo`; у субнормальных экспонента 0).
Экземпляры **мутабельны** (`q1.add(q2)` меняет `q1`), есть статические варианты (`Quadruple.add(q1, q2)`, создают новый
экземпляр) и формы с аргументами `long`/`double`. Документация API:
https://m-vokhm.github.io/Quadruple/src/main/javadoc/com/mvohm/quadruple/Quadruple.html

- Maven, JMH 1.37, Java 17; `Quadruple` подключён зависимостью из локального репозитория Maven (сейчас 1.2.0).
- `SimpleJmhBench.java` — JMH: сложение, вычитание, умножение, деление; `BigDecimal` (`MathContext` 38 цифр)
  против `Quadruple` в статической и экземплярной форме. `SimpleNanoBench.java` — то же на `System.nanoTime()`.
  `AuxMethods.java` — вывод.
- Сборка `mvn package` → `target/benchmarks-<quadruple.version>.jar` (shade), запуск `java -jar target/benchmarks-1.2.1.jar`.
- Результаты из README Quadruple (версия 1.2.0, OpenJDK 21.0.3, массивы 64K и 4M элементов) получены `SimpleJmhBench`.

## Что мерить

- Арифметика: `add`, `subtract`, `multiply`, `divide`, `sqrt` — экземплярная и статическая формы, только с
  аргументами `Quadruple`; `BigDecimal` для сравнения — только с аргументами `BigDecimal`. Формы с `long`/`double`
  не мерить: внутри та же арифметика плюс пренебрежимо малая конвертация — бесполезные данные.
- Преобразования: `toString()`, `bigDecimalValue()`, `doubleValue()`, `assign(double)`, `assign(BigDecimal)`,
  `assign(String)`. Конструкторы отдельно не мерить — конструктор создаёт пустой экземпляр и вызывает `assign()`.
- Данные: случайные, с фиксированным seed, распределение по битам мантиссы и по экспоненте (разные ветки кода);
  отдельные наборы для субнормальных и для операндов с сильно различающимися экспонентами — это другие ветки.
- **Мутабельная арифметика не должна выделять память в куче** — проверять профайлером `-prof gc`
  (`gc.alloc.rate.norm` ≈ 0 для экземплярных форм).

## Известные проблемы текущего кода

- `@Setup(Level.Invocation)` при операциях в десятки наносекунд — JMH прямо предупреждает: накладные расходы
  и искажение времени сопоставимы с самой операцией. Обновление данных — на `Level.Iteration` или иначе.
- Экземплярные бенчмарки накапливают результат в операндах (`op1[i].add(op2[i])`), значения уплывают между
  обновлениями; индекс — общее состояние в `@State`.
- Уникальна только 1/8 данных, остальное — копии; `@Fork(1)`; данные только в диапазоне `[0, 1e39)`.
- Старые версии плагинов (compiler 3.8.0, shade 3.2.1 и др.).

## Сравнение версий Quadruple

Версия зависимости задаётся свойством (`-Dquadruple.version=…`); сравниваемые версии ставятся в `~/.m2` через
`mvn install` в проекте Quadruple (1.2.1 — из тега `v1.2.1`, рабочая версия рефакторинга — например 1.2.2-SNAPSHOT).
Одна и та же сборка бенчмарков, одна машина, одинаковые параметры JMH; результаты сохранять (`-rf json`) для сравнения.
